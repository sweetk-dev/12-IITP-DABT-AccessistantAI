# AccessistantAI — 장애인 정책 음성 Q&A 서비스 (백엔드)

장애인 복지 정책에 대한 자연어/음성 질의응답을 제공하는 FastAPI 기반 백엔드.

## 구성

- **`welfare_backend/`** — FastAPI + PostgreSQL + pgvector 백엔드
  - `main.py` — 정책 검색·요약 도구 5종을 노출하는 API 엔드포인트
  - `live_bridge.py` — 음성·텍스트 멀티모달 WebSocket 브릿지
  - `tool_handlers.py` — Function Calling 핸들러
  - `database.py` / `models.py` / `schemas.py` — DB 연결, ORM, 스키마
  - `policy_db/` — 정책 데이터 정의 (`items/`, `schema.json`), 인제스트(`ingest_sync.py`), 자동 갱신 크롤러(`crawler/`)
  - `scripts/` — 배치 작업 (임베딩 백필, 주간 리포트, 오래된 쿼리 정리 등)
  - `static/` — 마이크 워커, 진입 페이지(accessistant.html)·관리자 콘솔
  - `reports/unresolved/` — 미해결 질의 주간 리포트
- **`docs/handoff/`** — 설계·아키텍처 문서
  - `SERVICE_OVERVIEW.md` — 서비스 전반 개요 (구성·플로우·운영 가이드)
  - `system_architecture.html` — 시스템 아키텍처 도식

## 기술 스택

- 언어/프레임워크: Python 3.x, FastAPI, uvicorn
- DB: PostgreSQL + pgvector (`welfare_db`)
- 외부 API:
  - Gemini Multimodal Live API (음성·텍스트 멀티모달 대화 + 임베딩)
  - LLM (정기 크롤러 갱신안 생성 + 주간 리포트 의도 클러스터링): 기본 Gemini. 환경변수 `LLM_BACKEND` 로 온프레미스 Gemma 교체 가능 (외부 API는 Google로 단일화)
- 데이터 처리: trafilatura, beautifulsoup4, readability-lxml, pypdf
- 빌드(별도 데모): PyInstaller

## 백엔드 실행

```bash
cd welfare_backend

# 1) 환경변수 준비
cp .env.example .env
# .env 를 열어 DB_PASS, GEMINI_API_KEY 채우기

# 2) 의존성 설치 (필요 시)
pip install fastapi uvicorn psycopg2-binary pgvector google-genai
pip install trafilatura beautifulsoup4 readability-lxml pypdf jsonschema httpx

# 3) 서버 기동
uvicorn main:app --reload --host 127.0.0.1 --port 18000
```

필요한 환경변수 템플릿: `welfare_backend/.env.example`

## 대중교통 구간 안내 — 실시간 저상버스·역 편의시설 (v1.39.0)

경로 안내의 버스 구간은 "저상버스 정차는 보장되지 않는다"는 고정 경고만 냈고, 지하철 구간은 승강기 개수만 알았다.
경로 서비스(02 v1.19.0)가 경기버스정보(GBIS) 도착·위치 API 와 국가철도공단 역 설비 자료를 붙이면서 이 비서도 그것을 말하고 보여 준다.

| 도구 | 발화 예 | 동작 |
|---|---|---|
| `get_bus_arrivals` | "저상버스 언제 와", "다음 버스 저상이야", "51번 몇 분 남았어" | 정류장의 실시간 도착정보. 안내 중이면 승차 정류장·노선이 세션에서 자동 주입되고, 아니면 말한 장소·현재 위치의 가장 가까운 정류장을 쓴다. 저상 차량이 안 잡히면 "지금 오는 차 중엔 없다"로 말한다(없다고 단정하지 않음) |
| `get_station_facilities` | "범계역 엘리베이터 어디 있어", "안양역 장애인 화장실 있어" | 승강기·리프트 출입구별 위치, 장애인화장실 게이트 안/밖·출구, 승강장 안전발판·열차 이격거리. 유무는 3상태 — `unknown` 은 "자료 없음"이지 "없음"이 아니다 |
| `plan_accessible_route` (보강) | — | 대중교통 조합 요청 시 `realtime=true` 로 승차 정류장 도착정보를 함께 받아 `low_floor_note` 로 요약. 지하철 leg 에 승·하차 역 설비 요약 |
| `find_nearby_transit` (보강) | — | 역 항목에 승강기 수·리프트 수·장애인화장실 3상태를 실어 보낸다 |

화면(`accessistant.html`): 버스 구간 카드가 실시간 확인 결과("저상 2번 약 4분 후 도착")를 고정 경고 대신 보여 주고, 안내 중 승차 스텝에서는 20초 간격으로 갱신하며 저상 차량이 확인되면 1회 음성으로 알린다. 지하철 카드에는 승차역 승강기 출입구와 장애인화장실 유무가 붙는다. REST 미러: `GET /api/v1/tools/bus_arrivals`, `GET /api/v1/tools/station_facilities`.

## 길안내 음성 — 끊기지 않는 스텝 안내 (v1.43.0)

실보행 시뮬레이션(운영 경로 8건 × 속도·GPS 잡음 10회, `91-조사설계_이동편의/실보행_안내음성_끊김_시뮬레이션_2026-09-02.md`)에서
스텝 안내의 25% 가 다음 안내에 잘렸고, 횡단보도 노드 스텝(거리 0, 다음 링크 스텝과 같은 좌표) 뒤에서는 87% 가 1초 만에 끊겼다.
스텝 전환이 "다음 지점 25m 이내"만 보고 일어나고, 새 안내가 재생 중인 안내를 즉시 끊는 구조 때문이었다.

- **발화 큐** — 스텝 안내는 앞 안내를 끊지 않고 이어서 말한다(대기 상한 3개). "다음 안내까지 300m" 같은 중간 안내는 스텝 안내가 대기 중이면 버린다. 이탈·출발지 지정 등 상태 안내는 종전처럼 즉시 발화(대기열 폐기).
- **횡단보도 병합 발화** — 노드 스텝과 다음 링크 스텝을 한 문장으로 말한다: "횡단보도가 있습니다. 횡단보도를 건너 12m 이동합니다. (턱낮춤 미상)". 화면 스텝 카드는 그대로 두 개다.
- **전환 판정** — 반경 25m 는 필요조건으로 두고, 경로 진행거리가 스텝 지점의 (앞 스텝 길이의 절반, 5~25m) 전에 도달했을 때 전환한다.
- **모의 주행** — 안내 음성이 재생 중이면 가상 이동을 멈춘다(배속과 무관하게 모든 안내를 끝까지 듣는다).

같은 시뮬레이션 재측정: 잘림 464건 → **0건**, 큐 대기 지연 중앙값 0초·최대 5초.

### 서버 합성 지연에 안전한 발화 (v1.43.1)

실기기 모의주행에서 안내가 한두 글자에서 잘리거나 아예 나오지 않고 넘어가는 현상이 남아 있었다. 서버 음성 합성(`/api/v1/tts`, Gemini TTS)은
캐시 미스일 때 5~9초가 걸리는데(운영 서버 실측), 발화 큐가 재생 종료 시각을 "요청 시각 + 추정 길이"로 잡아 음성이 시작되기도 전에
끝난 것으로 보고 다음 발화가 앞 것을 끊거나(잘림) 늦게 도착한 합성을 폐기(무음)했다. 합성 지연을 주입한 모의주행 재현(운영 경로 8건):
잘림 18%·무음 7%.

- **합성 대기 단계** — 재생 종료 판정은 실제 재생 시작 시각 + `Audio.duration` 기준. 합성 대기 중에는 큐도 모의주행도 기다린다.
- **대기 상한 12초** — 합성이 그보다 오래 걸리면 기기 내장 TTS 로 대신 말한다(늦게 온 서버 음성은 재생하지 않고 캐시에만 남긴다).
- **프리페치** — 경로가 표시되는 시점부터 안내 문장을 2개 병렬로 미리 합성하고, 같은 문장의 진행 중 요청은 공유한다.
- **모바일 브라우저 음성인식 비활성** — Android 는 인식이 시작될 때마다 OS 효과음이 나고 침묵·TTS 재생마다 재시작돼 효과음이 반복됐다.
  음성 입력은 마이크 PCM→웹소켓 경로라 영향이 없고, 사용자 발화 자막은 턴 종료 시 백엔드 전사로 표시된다.

재현 하네스 재측정: 합성 지연 5~9초에서 잘림·무음 **0건**(456 발화), 합성 실패 30% 주입 시에도 0건(내장 TTS 폴백), 지연 13~15초에서는 폴백 8건·잘림 0건.

### 실기기 확인 라운드 2 (v1.43.2)

- **도보만 요청** — "도보로", "걸어서" 라고 말해도 경로 도구의 `mode` 가 비어 자동 추천(거리 700m 이상이면 버스 조합)이 적용됐다.
  프롬프트·도구 스키마에 도보 키워드를 명시해 `mode: walk` 로 잡는다.
- **안내가 "다음…" 에서 끊기고 8초 뒤 "안내를 이어갈게요"** — 스피커로 나간 안내가 마이크로 되돌아와 barge-in 으로 판정된 것.
  모의 주행에서는 barge-in 을 쓰지 않고, 실안내에서는 임계를 0.035·0.8초로 올린다. barge-in 은 서버 로그에 남긴다.
- **서버 합성 한도** — 음성 합성 모델의 일일 요청 한도(무료 등급 100회)를 넘기면 이후 요청이 모두 실패해 기기 내장 TTS 로 넘어갔다.
  합성 결과를 디스크(`TTS_CACHE_DIR`, 기본 `/data/tts_cache`)에도 저장해 재시작·재배포에도 같은 문장을 다시 합성하지 않고,
  한도 소진 응답을 받으면 쿨다운 동안 즉시 503 을 돌려 화면이 지체 없이 폴백한다(프리페치도 중단). 일시 오류는 1회 재시도, 동시 합성 2개.

### 실증 라운드 3 (v1.44.0)

2026-09-03 오전 실증(안양문화원·안양시청 구간, 경로 9건·제보 17건)에서 나온 화면 결함을 고친다.

- **지도 자동 재시도** — 지도를 불러오지 못하면 10초→20초→40초→이후 60초 간격으로 다시 시도하고, 망 복귀 이벤트가 오면 즉시 시도한다.
  늦게 뜬 지도에는 현재 위치·출발지·관광지 태그·경로선·안내 지점 마커를 그대로 복원한다.
- **도착 후 자동 종료** — 도착 안내가 끝나면 "안내를 종료합니다"를 말하고 이동·관광 첫 화면(관광지 목록)으로 돌아간다.
  종전에는 서비스를 나갔다 들어와야 다음 목적지를 고를 수 있었다.
- **지도 영역 최소 높이·시트 손잡이 고정** — 경로 요약(이동 방식 카드)이나 답변 스트립이 커지면 지도가 180px 까지 줄어 신고 버튼이 상태 배너까지
  올라갔다. 지도는 화면의 36%(200~380px)를 지키고 시트가 대신 줄어 스크롤하며, 손잡이는 시트 맨 위에 고정된다.
- **경로 이탈 판정 완화** — 45m 를 4회 연속·12초 이상 벗어나야 이탈로 본다. 버스·지하철 승차 구간(정류장을 이은 개략선)은 판정하지 않고,
  경로 시작점에 아직 못 미친 상태(출발지가 보행망 노드로 스냅돼 시작점이 떨어져 있는 경우)와 정확도 40m 초과 위치도 세지 않는다.
- **지도 탭 출발지 변경 확인** — 경로가 떠 있거나 안내 중일 때 지도를 누르면 바로 옮기지 않고 "출발지를 변경할까요?" 를 묻는다.
- **현재 위치 버튼** — 신고 버튼 줄 우측. 지도를 끌면 안내 중에도 카메라 추적이 풀려 주변을 볼 수 있고, 버튼을 누르면 현재 위치로 돌아오며 추적을 재개한다.
- **구간별 경로선** — 도보 구간은 실선, 버스·지하철 구간은 점선(보라)으로 나눠 그린다. 대중교통 구간 선은 정류장 좌표를 이은 개략선이라
  실제 차로와 다르다는 점이 드러나도록 했다(실제 노선 형상은 경로 서비스 쪽 후속).

### 길안내 음성 Cloud TTS 전환 · 안내 중 음성 입력 (v1.45.0)

- **길안내 음성 = Google Cloud Text-to-Speech(Neural2)** — `GCLOUD_TTS_API_KEY` 가 있으면 `ko-KR-Neural2-A`(여성)/`-C`(남성)로
  합성한다(`TTS_PROVIDER=gcloud`, REST `text:synthesize`, LINEAR16 24kHz). 실패하면 Gemini 보이스, 그것도 안 되면 기기 내장 TTS.
  합성 결과는 provider 별 디렉터리(`gc-<voice>`)로 디스크 캐시. 응답 헤더 `X-TTS-Provider` 로 어느 쪽이 냈는지 알 수 있다.
  Gemini TTS 프리뷰 모델의 일일 100회 한도(2026-09-03 실증 중 소진)를 피하기 위한 전환이며, 상담 목소리와 길안내 목소리는 달라진다.
- **안내 중 질문이 인식되지 않던 문제** — 두 가지가 겹쳐 있었다.
  ① 안내 음성 재생 중 마이크 게이트가 0.035 를 6청크 **연속**으로 요구해 음절 사이 숨마다 리셋됐고(실증 당일 barge-in 0건),
  닫힌 동안 프레임을 버려 질문 앞부분도 사라졌다 → 최근 8청크 중 4청크 ≥0.028 창 판정 + 판정 전 1초 프리롤을 함께 전송.
  ② Android 내장 TTS 는 `onend` 가 누락되는 일이 있어 재생 중 상태가 풀리지 않고 게이트가 닫힌 채 굳었다 →
  추정 길이×1.3+1초가 지나면 끝난 것으로 보고 게이트를 연다.
  브라우저 음성인식(v1.43.1 모바일 비활성)은 자막 전용이라 음성 입력과 무관하다.

## 장소 해석 — 기관명·상호·도로명주소 폴백 (v1.42.0)

경로 도구가 아는 장소 이름은 경로 서비스(02)의 무장애 관광지·지하철역·OSM 건물 이름뿐이었다.
이용자가 말하는 목적지에는 "국민건강보험공단 안양지사" 같은 기관명·상호와 "관평로 182" 같은 도로명주소가 흔한데,
둘 다 거기 없어 `place_not_found` 로 끝났다(미답변 로그 실측). 화면의 장소 검색창에는 v1.38.0 부터 카카오 장소검색(JS SDK)이
폴백으로 붙어 있었으므로, 같은 출처를 음성 도구 경로에도 붙였다.

장소 해석 순서: (1) 안양 지하철역 정적 매핑 → (2) 02 `/poi/search` 서비스 지역 안 → (2') **카카오 로컬** 키워드 → 주소
(서비스 지역 안 결과 우선) → 02 범위 확대 검색 → 카카오 지역 밖 결과("범위 밖" 안내 근거) → (3) 무장애 관광지 이름.
`GET /api/v1/tools/search_places` 도 02 결과가 없을 때 같은 폴백을 태우므로, 화면과 음성이 같은 장소를 본다.

- 모듈 `welfare_backend/kakao_local.py` — `KAKAO_REST_API_KEY` (REST 키, 화면용 `KAKAO_JS_KEY` 와 다르다). 키가 없으면 조용히 건너뛴다.
- 키워드 검색은 안양시청 반경 20km 거리순으로 부르고, 결과마다 서비스 지역 bbox 판정을 붙인다.

## 미답변 질의 탭의 두 층 (v1.41.0)

미답변 질의는 "정책 DB 도구로 답하지 못한 턴"을 전부 남긴다(발굴 원칙: 과잉 적재가 과소 관측보다 낫다). 그래서 상담원이 자기 지식이나 외부 검색으로 답을 한 턴도 함께 쌓이는데, 그것은 "답을 못 한 것"과 다르다. 적재는 그대로 두고 콘솔에서만 둘로 나눈다.

| 구분 | 폴백 사유 | 뜻 |
|---|---|---|
| **미답변(실패)** — 기본 | `empty_result` `explicit_no_info` `tool_error` `needs_input` `out_of_service_area` `unknown` (`low_similarity` `category_mismatch`) | 도구가 실패했거나 상담원이 답을 주지 못한 턴 |
| **발굴 후보** | `no_tool_call` `google_search` | 답은 했지만 정책 DB 없이 답한 턴 — 후속 판단은 발굴(LLM)에 맡긴다 |

같이 고친 것: 장소 이름을 못 찾은 `place_not_found`, 역 이름 없음, 주변 정류장 없음은 `needs_input` 으로, 실시간 소스 장애(`unavailable`)는 `tool_error` 로 판정한다(전에는 `unknown`). 경로 안내의 이동 방식 라벨은 **요청한 방식이 아니라 실제 구간(legs)** 으로 정한다 — 버스+지하철로 요청해도 플래너가 버스 직결만 고르면 "도보+버스"다.

## 상담 음성 품질 — 에코 억제·숫자 표기 (v1.40.0)

- **에코 억제**: 스피커로 나간 상담원 음성의 끝말("…드릴게요"의 "요")이 마이크로 되돌아와 사용자 발화로 전사·응답되는 일이 잦았다. 상담 화면에서도 상담원 음성 중·직후(재생 종료 후 800ms)에는 지속 발화(barge-in)가 감지된 뒤부터 마이크 프레임을 보내고, 그래도 들어온 짧은 전사가 직전 발화의 끝말과 같으면 서버·화면 모두 사용자 발화로 다루지 않는다(`text_normalize.looks_like_echo`).
- **숫자 표기**: 상담원 텍스트는 음성 전사라 "일오칠칠에 천번", "관평로 백팔십이"처럼 적혔다. 화면 말풍선과 대화 이력에서 전화번호(낱자 3자 이상 + 전화 맥락 → `1577-1000`)와 단위 수(십·백·천·만 + 단위/도로명 → `182`)를 아라비아 숫자로 바꾼다(`text_normalize.normalize_numbers`, 프런트 동일 규칙). 한 글자 수("이 층", "삼일")와 낱말("구사일생", "하십시오")은 손대지 않는다.
